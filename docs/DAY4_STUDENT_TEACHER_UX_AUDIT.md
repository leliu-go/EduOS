# Day 4 学生端与老师端 UX 审查

日期：2026-05-21

## 当前结论

学生端和老师端已经不是空壳，课表、作业、错题、资源、通知、学习报告、老师课程和作业批改等核心页面均已存在，并且大多数查询已经通过 `tenantId`、`userId`、`teacherId` 或班级授权做服务端范围限制。

主要问题不在“完全没功能”，而在产品体验还不够像正式学习 App / 教学执行 App：

1. 移动端底部导航把首页写成固定 active，进入课表、作业、错题等页面时仍高亮首页。
2. 学生端和老师端底部导航缺少“我的”入口，账号、安全、版本、帮助、退出登录等能力分散或不可见。
3. 学生端第五个底部入口是资源，老师端第五个底部入口也是资源，和 Day 4 信息架构不一致；资源应继续保留页面，但可从首页/作业/课程进入，不应挤掉“我的”。
4. `MobileShell` 桌面宽度限制为 `max-w-md`，在电脑上打开学生端/老师端会显得过窄、像手机截图，不利于老师桌面备课。
5. 学生首页内容较完整，但视觉组件仍偏分散，缺少统一的移动端任务卡片、状态标签、空状态组件规范。
6. 老师首页已有待办和今日课程，但课程详情、活动进度、班级学生详情仍需要后续继续做深。
7. 学生端缺少独立活动页，单词打卡目前更多依赖首页任务和活动后端能力。
8. 老师端缺少独立活动进度页，活动进度仍需和班级/作业工作流进一步整合。
9. 学生/老师“我的”里的账号安全、MFA 状态、缓存清理、帮助入口需要补齐。
10. 部分移动端页面仍是页面内自定义卡片，后续应逐步统一为共享组件。

## 已具备的学生端能力

- 学习工作台：今日课表、作业提醒、打卡任务、错题、资源、课时余额、学习任务。
- 我的课表：只读取当前学生所属班级/课程。
- 作业：待提交、已提交、订正和批改状态。
- 错题本：只读取当前学生错题，支持订正。
- 资源库：只读取授权资源和课程绑定资源。
- 学情报告：有出勤、作业、错题和建议入口。
- 通知、支付流水、课程资源详情页面已存在。

## 已具备的老师端能力

- 教学工作台：今日课程、待点名、待反馈、待批改、未提交、关注学生。
- 我的课表：只读取当前老师课程。
- 班级：读取当前老师授课班级和学生学习概况。
- 作业管理：布置作业、查看提交、批改、要求订正。
- 资源管理：查看/上传/绑定授权教学资源。
- 课程资源和课后反馈页面已存在。

## UI 问题

- 学生/老师端移动布局不够统一。
- 底部导航 active 状态错误。
- 缺少“我的”页。
- 桌面访问移动端时宽度过窄。
- 资源和活动入口没有形成清楚的学习/教学路径。
- 一些页面的 empty state 有，但还不够统一。

## 权限与安全观察

- 学生路由使用 `route:student`、作业提交使用 `homework:submit`、错题使用 `mistakes:viewOwn`、支付使用 `payments:viewOwn`。
- 老师路由使用 `route:teacher`，作业/资源/反馈均通过对应权限进入。
- `lib/rbac/permissions.ts` 中学生无 `route:dashboard`、`route:teacher`、`finance:*`；老师无 `route:dashboard`、`route:finance`、`finance:*`。
- 课表、作业、错题、资源查询大多包含 `tenantId` 和用户/老师/班级授权条件。
- 未发现学生能进入 Admin/财务后台的显式权限配置。
- 后续仍需继续用 e2e 覆盖深链越权和跨 tenant 场景。

## 本轮低风险实施范围

1. 修复移动端底部导航 active 状态。
2. 学生端底部导航调整为：首页、课表、作业、错题、我的。
3. 老师端底部导航调整为：首页、课表、班级、作业、我的。
4. 新增学生/老师“我的”页面。
5. 优化 `MobileShell` 桌面宽度和 safe area。
6. 增加学生/老师权限边界测试。
7. 更新学生/老师/Admin 业务闭环文档。
