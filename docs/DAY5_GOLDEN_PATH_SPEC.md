# Day 5 Golden Path Spec

日期：2026-05-21

## 目标

用一套虚拟 QA 机构数据验证 EduOS 从机构后台、老师端、学生端到财务端的关键业务闭环。目标不是新增孤立功能，而是发现流程断点、安全问题和低风险可修复缺口。

## 覆盖角色

- Admin / 校长 / 教务：管理学生、家长、老师、课程、班级、报名、排课、资源、活动和监督报表。
- Finance：人工收款、支付流水、退费申请/审批、课消流水和财务报表。
- Teacher：课表、班级、点名、作业、批改、资源、课后反馈、活动进度。
- Student：学习首页、课表、作业、错题、资源、活动打卡、报告和个人页。

## 验收链路

1. 建立 QA 租户、校区和角色账号。
2. 建立学生、家长绑定和老师档案。
3. 建立课程产品和班级。
4. 学生报名并生成课时账户、订单和人工收款。
5. 安排两节课，老师和学生端均可见。
6. 老师点名，学生打卡，课消流水可见。
7. 老师布置作业，学生提交，老师批改和要求订正。
8. 资源绑定班级/课次，学生只看授权资源。
9. 学生资源下载走服务端验权与 signed URL，不直接暴露旧 `fileUrl`。
10. Admin 创建单词打卡活动，学生打卡，老师/Admin 查看进度。
11. 财务录入续费或人工收款，支付流水和报表更新。
12. 财务发起退费申请，审批后调整课时账户并写审计日志。
13. 学生/老师/家长/财务做越权访问验证。
14. 管理端版本号和更新入口可见。

## 通过标准

- 无 P0 安全问题。
- 学生不能访问老师端、Admin、财务或其他学生数据。
- 老师不能访问财务、系统设置、其他老师班级或非授权学生。
- 所有受保护页面使用服务端 `requirePermission`。
- 资源下载必须先通过服务端验权。
- 财务关键操作写 audit log，不删除原订单和原收款。
- `pnpm lint`、`pnpm typecheck`、`pnpm test` 通过。
- Golden path e2e 在 QA seed 后可运行。
